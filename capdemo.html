Implementación del Modo Demo en Inertiastore

Se implementó un sistema de modo demo que, cuando está activo, impide crear, actualizar y eliminar registros del módulo Dashboard. Los usuarios pueden seguir navegando y viendo los datos, pero cualquier acción de escritura es bloqueada.

1. Archivo de configuración: config/demo.php

Se creó un archivo de configuración con una clave enabled que por defecto es true. Esto permite controlar el modo demo desde el archivo .env sin tocar código, usando la variable DEMO_MODE.

2. Middleware: app/Http/Middleware/DemoMode.php

Se creó un middleware con un único método handle() que se ejecuta en cada petición. Su lógica es simple: si el modo demo está desactivado, deja pasar la petición sin intervenir. Si está activo, verifica el método HTTP de la petición. Si el método es POST, PUT, PATCH o DELETE (es decir, cualquier método que modifique datos), bloquea la petición, muestra un mensaje flash de Inertia indicando que la acción no está permitida en modo demo, y redirige al usuario de vuelta a la página anterior. Las peticiones GET no se ven afectadas.

3. Registro del middleware: bootstrap/app.php

Se registró el middleware con el alias 'demo' usando el método $middleware->alias(). Esto permite referenciarlo en las rutas por su nombre corto.

4. Aplicación a rutas: routes/web.php

Se agregó el middleware 'demo' al grupo de rutas del Dashboard, que incluye los recursos category, post y tag, más las rutas adicionales de subida y eliminación de imágenes. Como el middleware se aplica a nivel de grupo, todas las rutas del Dashboard heredan la protección automáticamente.

Resultado final

El modo demo está activo por defecto. Cualquier intento de crear, editar o eliminar un registro desde el Dashboard recibe un mensaje de error y la acción es rechazada. Para desactivarlo, basta con agregar DEMO_MODE=false en el archivo .env y no requiere cambios adicionales en el código de los controladores.
